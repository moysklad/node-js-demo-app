# Срез «Программа лояльности» (Loyalty API)

Образец необязательной точки встраивания: решение подключает программу лояльности
к аккаунту МоегоСклада и выступает провайдером Loyalty API (Discount API).

## Что демонстрирует

- Вкладку «Программа лояльности» внутри основного iframe (у решения один основной iframe —
  разделы вендор организует внутри своей страницы сам).
- Передачу настроек (`url`, `token`, `externalSearch`) в МойСклад через
  `PUT /apps/{appId}/{accountId}/loyalty` Vendor API, с разбором ошибок и подсказками.
- Заглушку методов Loyalty API, которые вызывает МойСклад, включая внешний поиск покупателей.
- Хранение подключения и его жизненный цикл при Install/Suspend/Uninstall решения.

## Платформенные особенности (важно)

- `<loyaltyApi/>` в дескрипторе — только «пропуск» на `PUT .../loyalty`: без него Vendor API
  отвечает ошибкой `2006`. Сам по себе элемент ничего не включает и на каталог не влияет.
- **Первый успешный `PUT .../loyalty` может включить программу лояльности как активную
  скидочную систему аккаунта**, если других активных скидок на нем нет. На рабочем аккаунте
  это меняет поведение Точки продаж — подключайте демо на тестовом аккаунте.
- При **Uninstall** МойСклад удаляет настройки лояльности на своей стороне; при **Suspend** —
  только приостанавливает. Поэтому решение хранит признак `connectedAt` и сбрасывает его
  при Install/Uninstall, сохраняя токен (см. `lifecycle.ts`).
- В ответе внешнего поиска покупателей поля `id` и `msId` МойСклад разбирает как **UUID** —
  произвольные строки не пройдут.
- Подключение опционально: на статус решения (`SettingsRequired`/`Activated`) оно не влияет,
  у него собственный индикатор на вкладке.

## Карта файлов

| Файл | Роль |
|---|---|
| `index.ts` | `registerLoyalty(app)` — точка подключения к ядру; `loyaltyIframeLocals()` — данные вкладки для рендера |
| `lifecycle.ts` | Реакция на Install/Uninstall решения: сброс признака подключения с сохранением токена |
| `types.ts` | Типы контрактов Loyalty API и данных подключения |
| `vendor-api.ts` | Клиент `PUT .../loyalty` + разбор ошибок Vendor API с подсказками (2004/2006/2007) |
| `connect/router.ts` | `POST /utils/connect-loyalty` — backend формы подключения (авторизация по `contextNonce`) |
| `provider/router.ts` | Заглушка провайдера Loyalty API: методы, которые вызывает МойСклад, авторизация по токену |
| `provider/demo-customers.ts` | Демо-база покупателей для внешнего поиска |
| `domain/` | Модель и SQLite-хранилище подключения (токен шифруется) |
| `iframe/tab.ejs` | Разметка вкладки — partial, включается из `src/features/entry/iframe/view.ejs` |
| `iframe/tab.ts` | Клиентская логика вкладки: диалоги, отправка формы подключения |
| `iframe/tab.css` | Стили вкладки — второй `<link>` на странице iframe |

## Швы в ядре

Все касания общего кода помечены: `grep -rn "feature:loyalty" src/ scripts/`.

- `src/app.ts` — вызов `registerLoyalty(app)`;
- `src/api/vendor-endpoint.ts` — хуки `loyaltyLifecycle.onInstall/onUninstall`;
- `src/utils/descriptor.ts` — `<loyaltyApi/>` в дескрипторе;
- `src/entry/router.ts` — `loyaltyIframeLocals()` в рендере iframe;
- `src/features/entry/iframe/view.ejs` — кнопка вкладки, `<link>` на css, `include` partial'а;
- `src/features/entry/iframe/client.ts` — вызов `initLoyaltyTab()`;
- `scripts/build-client-assets.mjs` и `build:assets` в `package.json` — сборка `tab.css`/`tab.ejs`.

## Как взять срез за основу

1. Скопируйте каталог `src/loyalty/` в свое решение.
2. Подключите швы из списка выше (начните с `registerLoyalty(app)` и `<loyaltyApi/>` в дескрипторе).
3. Замените заглушки `provider/` на бизнес-логику: хранение участников и балансов,
   правила скидок, начисление и списание бонусов, идемпотентность.
4. Реализуйте необязательные методы, если они нужны: `POST /counterparty/verify`
   (подтверждение регистрации кодом), `POST /retaildemand/verify` (подтверждение списания),
   `GET /giftcard` (подарочные сертификаты).
5. Прогоните тесты — они фиксируют контракт: `tests/loyalty-*.test.ts`
   (провайдер, подключение, жизненный цикл, хранилище, клиент Vendor API).

Детали реализации, о которых спотыкаются чаще всего: токен сохраняется **до** обращения
к Vendor API (иначе при сбое МойСклад знал бы токен, которого нет у решения, и все запросы
Loyalty API получали бы `401`); экран авторизации/регистрации в диалоге — демонстрация
сценария, реальная авторизация во внешней программе лояльности не выполняется.
